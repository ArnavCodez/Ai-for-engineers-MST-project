Motor Winding Virtual Sensor

The copper winding of an electric motor wears out fast when it runs hot, but a sensor buried inside it is costly and fragile. We trained a model that estimates the winding temperature of a 50 kW motor from eight signals its controller already measures. Replay it below on six test sessions it never saw while it was being built.

Thermal memory · Phase 3 features, Phase 6 memory curve

Why the model needs memory

Copper heats up slowly. The temperature now depends on how hard the motor worked over the last minutes, not only on the current right now. So we give the model running averages of each signal (EWMA, an exponentially weighted moving average) over 1, 5, 15 and 45 minutes. The longer averages look much more like the temperature curve.

Phase 4 cross-validation · Phase 5 test

Nine models, judged on sessions they never saw

Every model got the same 118,980 training rows and the same five folds. Each fold holds out whole sessions, so every score is on unseen sessions. The three finalists were then tested once on the six test sessions.

Phase 5 importance · Phase 6 ablation

What the model relies on

Two ways to ask the same question. Ablation retrains the MLP without a group of features and measures the cross-validation error. Permutation importance shuffles one group of signals in the test data and measures how much worse the final model gets.

Phase 6 · safety alarm on all six test sessions

Trade missed overheating for false alarms

The MLP reads too low when the winding is hot. A safety margin makes the alarm fire earlier: alarm when the estimate + k × σ reaches the hot level, where σ = 4.96 °C is the MLP's error spread in cross-validation (training data only). A bigger k catches more hot moments and raises more false alarms.
