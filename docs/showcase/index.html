Can we read a winding's temperature without a sensor?

A motor's copper winding ages faster the hotter it runs, but a sensor buried in it is costly and fragile. We want a model that works out the temperature from signals the controller already measures. This page shows what the data told us before we built anything.

Why the temperature matters

Each insulation class (IEC 60085) has a maximum hot-spot temperature. A common rule of thumb says insulation life halves for every 10 °C hotter. Our data never goes above 141.36 °C, which is below Class F.

Phase 2 · finding

The winding remembers

Heat is made by current squared (I²R), but the temperature doesn't jump when the current does. We shifted each session's temperature later in time and checked how well it lines up with the current. The match is best a few minutes later, so the model needs a memory of the recent past.

Phase 2 · summary

Five things the data told us

  1. The forbidden temperatures would leak. stator_tooth reaches r = with the target, while the best allowed input reaches only |r| = (i_d).
  2. No single signal is enough. At the same current the winding can be cold or hot. We need several inputs together, and non-linear models.
  3. The winding has thermal memory. It follows the heating current a few minutes late (median best lag min). That's why Phase 3 adds averages of the recent past (EWMA features over 1, 5, 15 and 45 min).
  4. Coolant sets the floor, with its own delay. The winding is usually °C above the coolant, yet in % of rows it is below it, right after the coolant has been heated.
  5. Sessions are very different. Session medians run from to °C. So we split by whole sessions and report errors per session.
Data: Kaggle "Electric Motor Temperature" (wkirgsn), version 3, Paderborn University LEA test bench. Training sessions only; test sessions stay locked until Phase 5. Every number here comes from outputs/results/eda_summary.json and notebooks/02_eda.ipynb in the team repo.
